# IFSC-Teste_Selenium

Cada grupo deverá escolher um site para ser testado. Nesse site deve ser testado ao menos 4 funcionalidades diferentes que resultaram em 4 testes. Sugere-se o seguinte roteiro para o trabalho:
•	Inicialmente deve ser escolhido um site, é importante que assim que o grupo escolha o site já tente verificar o seu funcionamento com o Selenium, se vocês conseguem pegar e manipular elementos HTML. Caso necessário o site pode ser trocado, porém dois grupos não podem utilizar o mesmo site. O site pode ser inclusive de algum projeto próprio de vocês (como algum feito por exemplo na UC de desenvolvimento web). Para que se tenha esse controle todos comunicam no moodle em espaço adequado (item TRA1) a sua escolha e assim estarão com aquele site “reservado”.
•	Em segundo momento deve ser pensado e escrito as quatro funcionalidades que serão testadas. Com isso vocês já podem realizar o primeiro envio.
•	Após deve ser programado os testes projetados. Nesse momento deve-se utilizar boas práticas de codificação de testes vistos em aula, principalmente o padrão Page Objects.
•	Na sequencia deverá ser feito um documento, o relatório de testes, conforme modelo em anexo, nesse será possível detalhar o site que será testado e cada teste: funcionalidade testada, iteração realizada, saída esperada, resultado obtido, observação sobre o teste.
•	Por último faça uma apresentação para a data 09/12. Essa apresentação pode ser com slides, conter vídeos da execução dos testes, trechos de código e etc. O que deve constar na apresentação:
◦	O site e rápida descrição do que esse site faz.
◦	As funcionalidades testadas (explicando com prints do site, ou no próprio, o que será testado)
◦	Mostrar por cima o código dos testes evidenciando o uso de Page Objects (para saber mais considere a leitura do seguinte artigo) e biblioteca de testes unitários. Evidenciar claramente dificuldades encontradas e soluções adotadas.
◦	Mostrar os testes rodando (pode ser rodando na hora ou por vídeo)
◦	Mostrar rapidamente o relatório de testes.
